# C81 vertical-flow pass

Baseline: `bd5f07863a150cd51245b9c942502efa19d4014d`. This pass follows the five catalog flows
across route handlers, access/hooks, persistence, jobs, and browser evidence. It combines the
current reports rather than treating a unit test as proof of the whole flow.

## Signup → verify → login → reset/recovery

First-user bootstrap uses Payload's one-shot native registration and then closes the empty-install
path. Ordinary signup is rate-capped, verification and reset links are delivered through the SMTP
task, and the reset-token complement preserves the administrator-issued token when SMTP is disabled.
The C01 seed/reseed drill, first-user HTTP 4/4, auth suites, no-SMTP complements, and offline-signup
browser 1/1 cover the transitions. The accepted F-C23 findings remain the shared/targeted login
budget and registration-enumeration controls. Expired-session behavior on a deployed edge remains
unverified.

## Upload → validate → store → preview → export

`uploadBundles`/`parseFormat` pass through AST extraction and contract validation before ingest writes
plans, versions, resource rows, and taxonomy references. Preview and Preview-as-PDF apply the same
structural gates, while export jobs bind to the requested version and artifact cache. C40/C41 corpus,
body-limit, null-resource, taxonomy, PostgreSQL-fault rollback, preview 5/5, Preview-as-PDF 7/7,
teacher-key 12/12, DOCX/PDF sink, and C54 export suites cover the path. A public proxy with omitted or
chunked body limits and a production Gotenberg/cache deployment remain qualified gaps.

## Edit → immutable version → Official move → discussion/notification

The editor obtains a form-render grant, but save-as-new is the only authenticated version write.
Field-split hooks preserve system fields, semver allocation is plan-scoped, and Make Official moves
the pointer under a plan lock. Discussion references use immutable version labels and notification
enqueue is best effort with bounded budgets. C5.1, C30/C31 save/race/authority/Combine suites,
Official-pointer lock, discussions/messages, and the browser editor/lesson flows cover the edges.
The reliable two-writer Official-vs-Combine race remains open and is explicitly not inferred from
the inconclusive barrier attempt.

## Export/email request → queue → cache → delivery

Export/auth endpoints authorize the caller before enqueueing a job; the job key binds plan/version/
format, generated bytes are written to the configured cache, and email delivery is disabled with a
503 when SMTP is unavailable. C54 endpoint selections, job-statistics, enqueue integration, C70
restore/cache fault run, Mailpit DOCX/PDF sink, and no-SMTP email-a-doc complement cover this path.
The cache deletion failure is accepted as F-C70-001 because the helper reports success after a failed
delete; a wrong-old-document collision was not established.

## Session expiry mid-edit → recovery → restore

Client recovery captures owner-scoped unsaved content, uses CAS/fencing and expiry metadata, and
restore/save-as-new retires the token and cascades source/user/plan cleanup. Recovery HTTP 35/35,
kernel integration 76/76, edit-recovery access 8/8, save-as-new recovery 9/9, Combine context 18/18,
and the browser recovery/editor flows cover the persistence boundaries. Cross-device expiry timing,
screen-reader recovery messaging, and deployed session invalidation remain qualified follow-ups.

**Exit:** all five vertical flows were traced through code and current evidence. No additional
accepted finding was produced; the open race, proxy, deployment, and expiry gaps are preserved in
the summary and matrices.
