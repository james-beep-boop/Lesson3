## Findings

### R1 — Low: malformed favorite IDs bypass the new existence check

`app/src/collections/Favorites.ts`, `requireReadableFavoriteVersion`, added in #447.

`relId` returns null for both absent values and invalid serial IDs. Returning early for null therefore
lets supplied values such as 0, -1, 1.5 and 2147483648 skip the new lookup altogether. This is an
incomplete closure of F-C24-001, not a new authorization bypass introduced by the patch.

Checked the pinned Payload 3.92.0 source: `utilities/isValidID.ts` accepts any non-NaN number for
numeric IDs; `fields/validations.ts` does not check existence when `filterOptions` is absent. These
inputs can therefore reach Postgres and produce foreign-key, integer-syntax or range errors instead
of a controlled client response. No data is written by the failed insert.

An isolated execution of the actual hook confirmed that all four inputs return without a lookup or
an error. The follow-up distinguishes an absent field (leave required validation alone) from an
invalid supplied ID (400). Valid numeric and digit-string IDs retain their lookup/404 behavior.
Added integration and HTTP cases checking 400 and no favorite row for all four values. These new
wire/database cases require CI; they were not run against a local database during this review.

### R2 — Low: the required-key regression case cannot detect a reverted check

`app/tests/unit/ingestContract.spec.ts:24`, added in #447.

The original case provides `META: {}` and `constructor: 'x'`, then accepts any missing-required-field
message. Other missing fields make it pass whether required keys are checked with `in` or
`Object.hasOwn`. The four unexpected-property tests are useful and do detect the principal bug;
this fifth case does not protect the separate required-key change.

Replaced it with an inherited `META` and an assertion for exactly `META: required field missing`.
An isolated mutation probe confirms that the old case passes with the old required-key logic and
the replacement distinguishes it. Product contract logic is unchanged.
