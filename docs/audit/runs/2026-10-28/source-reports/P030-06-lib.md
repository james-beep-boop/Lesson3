**Candidates**

**C1 — Medium-low. Confirmed local reasoning against stated policy; hook behaviour unreviewed.**
- *Evidence:* `aresReleasePresentation.ts:31` treats `officialChangedBy != null` as the marker for a human change. The policy says the notice appears "never for a human change", and that related deletions clear nullable references.
- *Precondition:* An admin makes an ARES-release version Official (§7 permits this). That admin's account is later deleted, so `officialChangedBy` becomes null.
- *Expected:* No notice, because the change was human.
- *Actual:* The function returns a notice, since `officialChangedAt` is set, `officialChangedBy` is null, and the current Official has a `releaseFingerprint`.
- *Note:* These fields cannot tell a system change apart from a human change whose actor was deleted. A fix likely needs a non-clearing marker. That is a design decision, not something I can infer.
- *Repro test:* Call `officialUpdateNotice` with `officialChangedBy: null`, a non-null `officialChangedAt`, and an Official with a `releaseFingerprint`. Compare the result with the policy expectation.
