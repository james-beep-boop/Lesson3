## Purpose and invariants (as read)

- **Compare page:** diffs two versions of one plan area by area. Both versions must be readable. An explicit unresolved `?from=`/`?to=` shows a message and no substitute comparison.
- **Lesson page:** renders the selected version (explicit `?version=` or Official). An unresolvable explicit version is never replaced with Official. Edit, Make Official, Combine and Compare affordances are gated on editing access or Subject-Admin status.
- **First-user form:** posts to first-register, maps 403 to "already completed", and redirects to `/admin` on success.

## Candidates

**No confirmed correctness defects in the supplied ranges.** Each item below is an uncertain lead, not a finding.

**L1. Compare route is not gated by the same rule as its link.** Severity: unresolved (possibly low).
- Evidence: `lessons/[id]/page.tsx:180-200` states "Compare render only for editors" and shows the Compare link only when `canEdit`. `compare/page.tsx:74-81` checks read access only, with no `canEdit` check.
- Precondition: a Teacher without editing access requests `/lessons/<id>/compare?from=<a>&to=<b>` directly.
- Actual: the comparison renders.
- Expected: not determinable from the supplied policy. The excerpt and the page comment at `lessons/[id]/page.tsx:41` say Teachers can view every version. The gate may be intentional.
- Test: as a non-editing reader, request the compare route and assert the intended response. The owner decides which response is intended.

**L2. Compare header title and lesson header title come from different versions.** Severity: low, if confirmed.
- Evidence: `compare/page.tsx:83` uses `versions[0]` (oldest) `meta.substrand_name`. `lessons/[id]/page.tsx:109` uses the selected version's `meta.substrand_name`.
- Precondition: two retained versions of one plan whose `substrand_name` differs.
- Actual: the compare title can differ from the lesson title for the same plan.
- Expected: not stated by the supplied policy.
- Test: create two versions with different `substrand_name` values. Assert the compare and lesson headers agree, or document that they should not.

**L3. Null-user dereference is guarded only indirectly.** Severity: low, unverified.
- Evidence: `lessons/[id]/page.tsx:120` uses `user.id` unguarded. Line 124 guards `user != null`.
- Precondition: `requireUser` can return a null user. Its contract is not in range.
- Actual: safe only if `isEditorFor(null, …)` is always false and `requireUser` never returns null. Neither is shown in range.
- Test: call the page with an anonymous session and assert no exception.

**L4. First-register error handling.** Severity: low, UX.
- Evidence: `FirstUserForm.tsx:36-43` maps only 403 to a specific message. All other failures get a generic message. A network exception after a server-side commit reaches `FirstUserForm.tsx:45-46`, which says "Setup failed" although the administrator now exists.
- Precondition: the response is lost after the server commits.
- Actual: the user is told to retry. A retry then gets 403 and the "already completed" message, so the flow recovers.
- Expected: not stated in the supplied policy.
- Test: mock `fetch` to succeed server-side and then reject. Assert the copy and whether the user can recover.

**L5. Security claims rely on unreviewed code.** Not a candidate.
- `compare/page.tsx:50` and `lessons/[id]/page.tsx:292` inject HTML with `dangerouslySetInnerHTML`. Safety depends on sanitization in `htmlDiffCache` and `htmlSectionsCache`, which were not supplied. This claim remains unreviewed until independent review.
