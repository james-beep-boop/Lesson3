## Purpose and invariants

- **Email jobs** (`emailVersionArtifact`, `messagePing`, `passwordResetEmail`) send mail with `retries: 0` or `3`. Each reads current state at send time, and the passwordReset job reads the token from the user row rather than from the job input.
- **Artifact jobs** (`generateVersionArtifact`, `prewarmVersionArtifacts`) generate content-addressed cache entries. A vanished version is meant to be a no-op. Prewarm must never throw into its caller.
- **Expiry job** (`expireEditRecovery`) has no task input, so the policy is fixed.

## Candidates

**1. passwordResetEmail.ts:72-75 — silent completion on an expired token (uncertain lead, low–medium).**
The header (lines 8-9) says the "reset link is on its way" message is true because of retries. But if `resetPasswordExpiration` passes during retries, the handler returns `{output:{}}` with no send, log, or capture.
- Precondition: the token expires after enqueue but before the job succeeds.
- Expected: unclear. The excerpt does not say whether the send should happen or the failure should be logged. Dead links should not be sent, but the user-facing promise is not met either.
- Actual: the job completes silently.
- Test: seed a user with a live token and an expiration in the past, run the handler, and assert whether a send or a log/capture occurs.

**2. passwordResetEmail.ts:58-68 — deleted user fails and retries (confirmed local reasoning, low).**
The `findByID` is outside the `try` and lacks `disableErrors`. A deleted user throws `NotFound`, which is neither logged nor captured, and `retries: 3` (line 52) re-runs it. The file's own comment at lines 70-71 says a non-live state should return normally to avoid a retry storm.
- Test: delete the user, run the handler, and assert it returns without throwing and is not retried.

**3. messagePing.ts:49-60 and 71-78 — no read-state check at send time (uncertain lead, low).**
The zero-unread gate runs at enqueue (line 8). The send-time check only confirms that the message exists, so a message read in-app before `autoRun` runs still produces "You have a message waiting." The job also never checks that `messageId` belongs to `recipientUserId`, which is trusted input.
- Expected: unknown. The excerpt does not define whether the ping should be suppressed after a read.
- Test: create a message, mark it read, run the handler, and observe whether the email is sent.

**4. generateVersionArtifact.ts:144-149 — `findPendingExportJob` can throw instead of returning null (confirmed local reasoning, low).**
The SQL returns an id, then `findByID` runs without `disableErrors`. If the row is removed between the two queries, `NotFound` propagates. That breaks the `PayloadJob | null` contract, and `prewarmVersionArtifacts.ts:39-42` rejects the whole `Promise.all`, skipping both kinds (lines 69-71 log and capture).
- Impact: a missed warm and a spurious capture. The teacher falls back to the cold path.
- Precondition: completed jobs are deleted. The `passwordResetEmail` header asserts this, but it is not verified here.
- Test: stub the row to vanish between the SQL query and `findByID`, then assert `null`.

**5. emailVersionArtifact.ts:68-74 vs generateVersionArtifact.ts:70-83 — inconsistent vanished-version handling (uncertain, low).**
The email job fails and captures when the version is gone. The artifact job treats the same condition as a no-op, and its comment argues that treating it as a failure trains people to ignore real captures. No policy in the excerpt settles which applies to email.
- Test: enqueue both jobs with a missing `versionId` and compare the outcomes.
