## Candidates

**C1. Confirmed by reading: non-ASCII letters break Title Case.** Severity: low (display chrome only).
- Evidence: `displayTitle.ts:15-16`. `toLowerCase()` leaves accented letters lowercase. The regex `(^|[^a-zA-Z'’])([a-z])` treats an accented letter as a word boundary, so it capitalises the next ASCII letter mid-word, and never capitalises an accented initial.
- Preconditions: an all-caps title with non-ASCII letters, for example `CAFÉS` or `ÉCOLE`.
- Expected (from the file's own comment, "renders in Title Case"): `Cafés`, `École`.
- Actual, by regex trace: `CaféS`, `éCole`.
- Focused reproduction (not run):
  ```ts
  expect(displayTitle('CAFÉS')).toBe('Cafés')
  expect(displayTitle('ÉCOLE')).toBe('École')
  ```
  Both should currently fail.
- Caveat: the excerpts give no non-ASCII casing policy, so the expected values are inferred from the comment's intent.

**C2. Uncertain lead: Combine suggestion does not see the current Official.** Severity unassessed.
- Evidence: `draftCombineSuggestion.ts:12-16` takes no Official argument. The candidate filter at `:37-44` and the release/descendant choice at `:45-59` never check Official. Any readable ingested release newer than the source is eligible, and the newest one wins.
- Policy excerpt: the trigger is "surviving ARES ancestor older than the current ARES Official", and "a version already based on the current Official has no suggestion."
- Possible repro: plan with O `1.0.0` (Official, id 1); S `1.0.1` (id 2, lineage `[1]`, author T, editor of the subject-grade); R `2.0.0` (id 3, release, lineage `[1]`, no author or second parent). The function returns R as `release`. Policy would expect `null`, because S is already based on the current Official. This holds only if the caller does not gate it, and the caller is not in range.
- Separately, `kind: 'descendant'` (`:51`) suggests any later version that descends from the source. The excerpts never describe that path, so its expected behaviour cannot be judged.
