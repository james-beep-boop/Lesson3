## Purpose and invariants

- **discuss/page.tsx**: server-rendered topic list and title search. Pinned topics, then latest-activity topics, 20 per page. Search is a GET form whose URL is the whole state. Forum-off mode hides write actions.
- **explore/page.tsx**: placeholder public route. Its docblock says `requirePublicLibrary()` is the access boundary and that an offline install must expose no public surface.
- **ForgotPasswordForm.tsx / page.tsx**: reset request. The docblock requires a response that does not reveal whether an account exists. The client must not add a `!res.ok` branch.

## Candidates

**1. Unawaited access guard: `explore/page.tsx:28` (uncertain lead, severity high if the guard is async)**
- Precondition: `requirePublicLibrary` is `async` or returns a promise, which the unseen file would determine.
- Expected: when the guard rejects, no public page renders.
- Actual (locally): `requirePublicLibrary()` is called without `await`. A rejected promise is discarded and the placeholder still renders. If the guard is synchronous and throws, this is fine.
- Repro: mock `requirePublicLibrary` as `async () => { throw new Error('off') }`, then `await expect(ExplorePage()).rejects.toThrow()`. The current code resolves, which would confirm the bug.

**2. 429 branch as a possible existence oracle: `ForgotPasswordForm.tsx:48-51` (unverified, medium if confirmed)**
- The client treats 429 as requester-only. That holds only if the server's per-address cap fires identically for registered and unregistered addresses. If the limiter counts only after lookup, 429 discriminates accounts.
- Expected: same 429 for any address at the same request count. Actual: not determinable from this file.
- Repro: integration test, two addresses (one real, one unknown), same request count, compare status codes and timing. This needs the server limiter.

**3. Moderator copy shown to everyone: `discuss/page.tsx:43` (lead, low)**
- Locally confirmed: the forum-off notice is unconditional and says "You can redact posts and delete threads here." The page never checks the caller's role.
- Expected (if §13 applies to text as well as controls): only roles that can redact see that sentence. Actual: all signed-in users see it.

**4. Pinned topics repeated on every page: `discuss/page.tsx:141-148` (lead, low)**
- Locally confirmed: `TopicList` renders `list.pinned` whenever it is non-empty, on any page.
- Whether pinned is repeated depends on `listTopics`, which is not supplied. Repeating pinned topics on page 2 may be intentional.
- Repro: call `listTopics` for page 2 with pinned topics and assert the pinned block is absent.

**5. Out-of-range search shows "no match" with no way back: `discuss/page.tsx:97-103` (lead, low)**
- Locally confirmed: when `results.rows` is empty, `SearchResults` returns before rendering `Pager` (lines 110-115). If `results.total > 0` and `page` is beyond the last page, the user sees "No discussion titles match" and no navigation.
- Depends on whether `searchTopics` clamps `page`, which is unseen.
- Repro: render `SearchResults` with `rows: []`, `total: 5`, `page: 3`, and check for a pager.

**6. SMTP-dependent UI copy: `forgot-password/page.tsx:14` (lead, low)**
- `smtpEnabled` is derived from `SMTP_HOST` alone. If the mail adapter is configured by other variables, the page can show "Contact your Site Administrator… no email needed" when email is in fact configured, or the reverse. The adapter config is unseen.

**Not a defect:** `ForgotPasswordForm.tsx:56` reports success on any non-429 response, including SMTP failure. The docblock documents this as a deliberate cost.
