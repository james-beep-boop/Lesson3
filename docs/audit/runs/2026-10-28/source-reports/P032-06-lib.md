Stated invariants: each destination has its own finding (line 863); reads have a deadline and fail to `null` (766-778); reads are size-bounded (780-784); the attempt tie-break goes to the failure (636-640); the restore state maps one-to-one to a message (651-712).

## Candidates

**C1. Size bound is not enforced during read (Low–Medium, confirmed by reading).**
- `backupStatus.ts:790-791`
- Precondition: a record file whose `stat().size` understates its content (size 0 on a streaming or procfs-like regular file). This requires write access to the record directory.
- Expected (from the code's own comment, 780-784): oversized content is never slurped.
- Actual: `file.readFile()` reads to EOF before the `> MAX_RECORD_BYTES` check, so the full content is buffered first. The check only rejects after allocation.
- Focused test: stub `open` to return a handle with `stat → {isFile: true, size: 0}` and a spied `readFile` that returns a 6 MiB buffer. Expect `read()` to return `null` and to avoid buffering the full stream. A mock returning a buffer will pass the current `null` result, so the test must assert on bytes consumed or on a streamed read.

**C2. `removable` is always true from the destination-aware path (Medium-Low lead, partly confirmed).**
- `backupStatus.ts:834` keeps the `usb` group unconditionally. `:942` passes the filtered groups in. `:934` returns `removable: destinations.some(d => d.kind === 'usb')`.
- Precondition: any call through `collectBackupStatus`, with no USB destination configured.
- Expected: unclear. The name and the use at 524-527 suggest it should track whether a removable destination is configured. This is a decision for the owner, not something to infer from the implementation.
- Actual: `removable === true` in every `collectBackupStatus` result.
- Focused test: call `collectBackupStatus` with `BACKUP_DISK_DIR` set and no USB or remote record. Assert `removable`. Impact depends on callers, which were not checked.

**C3. Unparseable `newestCovers` fails open to "ok" (Low lead, depends on unseen guard).**
- `backupStatus.ts:430` and `:444`
- Precondition: `coversUntil` is not a parseable date and passes the unseen `isStreamRecord` guard.
- Actual: `new Date(bad).getTime()` is `NaN`, so `now - NaN > limit.ms` is `false`, and line 444 emits `'ok'`.
- Expected: not stated by policy. The surrounding code uses `unknown` or `attention` for unusable evidence, so this is likely a mismatch, but that is an inference.
- Focused test: a record with `coversUntil: 'not-a-date'` and a valid `limit`. Assert the freshness state is not `ok`.

**C4. `isLater` ordering can be inconsistent (Low lead).**
- `backupStatus.ts:642-643`
- Precondition: events where `seq` is present on some and absent on others, or where `at` strings differ in format.
- Actual: the comparator mixes `seq` and time, so it is not transitive. String comparison of `at` is only correct for a uniform ISO-UTC format. The guard that enforces that format is unseen.
- Expected (from the 636-640 comment): the newest attempt wins, and a tie goes to the failure.
- Focused test: three attempts A(seq 2, at T1), B(no seq, at T2), C(seq 1, at T3). Check whether `reduce` gives an order-dependent result.

**C5. USB-kind technical label can say "A cloud location" (Low).**
- `backupStatus.ts:724`
- Precondition: per-destination call with `destinationKind === 'usb'` and a non-removable `destination`.
- Actual: the label is "A cloud location" because only `'disk'` and `isRemovableDestination` are checked.
- Expected: a label that matches the configured destination. Whether a non-removable USB destination is valid is unresolved.
