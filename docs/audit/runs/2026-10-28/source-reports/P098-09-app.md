## Candidates

**C1. Quiet buttons ignore the disabled/busy treatment (confirmed local CSS reasoning; user impact conditional).**
- Evidence: `.lp-btn--quiet` sets `color` and `border-color` directly (1886-1887, lines 1885-1906). The disabled/busy block (1911-1920) changes only custom properties (`--color`, `--btn-border`). Once `color` is set directly, `--color` no longer affects that element. The quiet selector is also more specific than Payload's own rules, so it wins.
- Precondition: a `.lp-btn--quiet` element that has `.btn--disabled`, `:disabled`, or `aria-busy="true"`. I cannot see whether any such element exists.
- Expected (per the comment at 1908-1910): unavailable/disabled ink.
- Actual, by cascade reasoning: quiet ink and quiet border, plus accent colour on `:hover`, which still matches disabled buttons.
- Severity: low. It is user-visible only if such a button exists.
- Reproduction test (not run): render `<a class="btn lp-btn lp-btn--quiet" aria-busy="true">` inside `.collection-edit--lesson-bundle-versions .lesson-controls-wrap`. Assert that computed `color` equals `--app-btn-disabled-ink`. Also assert that hover does not change `color`.

**C2. Hidden chrome may remove a function that its replacement does not cover (lead, unverified).**
- `.doc-controls__popup` is hidden (1632-1634). The comment says Delete was moved into `LessonControls`. If that promoted Delete does not cover every role that had kebab delete, those users lose the path.
- `.doc-controls .form-submit` is hidden (1623-1625). The comment says `LessonControls` is "the only control surface". Whether it covers every save and submit path is unverified.
- `.nav__log-out` is hidden globally (1603-1605). If the replacement logout is not on every admin page, users cannot sign out.
- Severity: unknown until the replacement components are read.

**C3. Timestamps may be hidden by default (lead, unverified).**
- The native meta row is hidden (1613-1615). The comment at 1609-1611 says the timestamps were relocated into the sidebar. The sidebar is `display:none` by default (1692-1694). Together, Last Modified and Created may not be visible unless "Show details" is pressed.
- Whether this is intended depends on the design, which is not in the supplied excerpts.

**Non-candidate (documentation only).** The comments at 1763-1764 and 1780-1782 say the container-scoped selectors and the opt-in class have the same specificity, and that the `&.btn--style-*` restatements land at 0-3-0. The container selector at 1788 is 0-3-0, and its nested restatements are 0-4-0. The stated invariant is wrong, but the outranking outcome still holds, so I am not reporting it as a defect.
