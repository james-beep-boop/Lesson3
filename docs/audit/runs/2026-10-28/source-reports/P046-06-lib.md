## Purpose and invariants (as stated in the code)

- **systemFlagNames.ts:** a dependency-free vocabulary. `SAVEABLE_FLAGS` is a deliberate subset of `SYSTEM_FLAGS`, excluding `publicLibraryLive`. That exclusion is documented as intentional.
- **systemFlags.ts:** fail-closed reads. Only an explicit stored `true` enables a flag. Reads are per request, with no cross-request cache.
- **txDb.ts:** transaction-bound DB access. It throws rather than falling back to the pool when a transaction session is unresolvable. `lockRows` takes ascending `FOR UPDATE` locks. `assertFresh` returns 409 on a stale token and fails closed on NaN.
- **userSearchContract.ts:** shared wire types and labels for the Users panel.
- **versionContent.ts:** `DROP_KEYS` and `SERVER_REL_KEYS` define what counts as version content.
- **versionCounts.ts:** a raw per-plan version count that deliberately uses the pool.

## Candidates

No confirmed product defects in the supplied ranges. The leads below are uncertain.

1. **Lead, medium-low: `app/src/lib/versionContent.ts:14-30`.** `DROP_KEYS` omits `officialChangedAt`, `officialChangedFrom`, and `officialChangedBy`. Policy says these are system-only change records, but it does not say whether they are excluded from content equality. If they are stored on version documents, `comparableContent` would treat an Official pointer change as a content change. That could affect the save-as-new no-op guard, the combine "same content" decision, and the older-release content flag.
   - *Precondition:* the fields exist on `lesson-bundle-versions`, which the supplied ranges do not show.
   - *Expected:* not stated by the policy excerpt, so no expected behaviour is asserted.
   - *Reproduction (once the expectation is decided):* two version docs identical except for `officialChangedAt`; assert `comparableContent` equality matches the decided policy.

2. **Lead, low-medium: `app/src/lib/versionCounts.ts:11-17`.** The docblock says "Caller authentication is required", but the function performs no check. It runs raw SQL on the pool, so any caller that omits auth reads per-plan counts.
   - *Precondition:* a caller that does not check auth. Callers were not supplied, so this cannot be confirmed.
   - *Expected:* the docblock says it mirrors `lessonBundleVersionRead` (`Boolean(user)`).
   - *Reproduction:* invoke through an unauthenticated request path and check whether counts are returned.

3. **Lead, low: `app/src/lib/versionCounts.ts:19-25`.** Rows that fail the `isSafeInteger` check are dropped silently. A caller sees a missing key, indistinguishable from a plan with no versions.
   - *Precondition:* a driver returns a non-integer count or plan id. Not demonstrated.
   - *Reproduction:* mock `execute` to return a non-numeric `versionCount` and assert whether the omission is signalled.

4. **Lead, low: `app/src/lib/txDb.ts:58-59`.** `id ? … : undefined` treats an empty-string `transactionID` as "no transaction". With `requireTransaction` unset, the statement then runs on the pool.
   - *Precondition:* `transactionID === ''`. Unlikely; Payload likely never produces it.
   - *Reproduction:* `txDb({ payload, transactionID: '' })` with `requireTransaction` unset, expecting throw under the fail-closed docblock.

5. **Unverified, not a defect: `app/src/lib/userSearchContract.ts:12, 31`.** `UserTypeLabel` is imported from `../access`, which was not supplied. The label map's agreement with that type cannot be checked.
