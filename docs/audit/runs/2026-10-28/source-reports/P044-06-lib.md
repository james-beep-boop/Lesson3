## Purpose and invariants

- **resolveLessonReferences:** two viewer-scoped batched reads. A null or unreadable `refVersion` yields no links.
- **sanitizeHtml:** DOMPurify allowlist for preview HTML, plus `target=_blank` for http(s) links.
- **schoolMetadata:** page title from the school name, with fallback.
- **schoolName:** shared name rules (one line, no control characters, trimmed, max 80).
- **semver:** bump, compare, and next-free-version helpers.
- **serverActionBodyLimit:** a 12 MiB ceiling, derived from a measured 2.57× form-state multiplier. The arithmetic checks out: 4,000,000 × 2.57 = 10,280,000 ≤ 12,582,912, and the rounding is upward.
- **session:** cached `payload.auth` lookup and login redirect.
- **setSchoolName:** trusted transactional global update under an advisory lock.
- **stripIds:** deep copy without `id` keys.

## Candidates

**1. Low, confirmed local reasoning.** `schoolName.ts:17`
The length check uses `name.length` (UTF-16 code units), but the error says "characters."
- Precondition: a name containing astral characters, such as emoji.
- Expected, per the message's unit: 41 emoji (41 characters) accepted.
- Actual: rejected, because 41 × 2 = 82 > 80.
- Test: `expect(() => parseSchoolName('😀'.repeat(41))).not.toThrow()`
- Whether the limit should count code points or graphemes is a policy question I have not decided.

**2. Low, local reasoning with an assumption.** `sanitizeHtml.ts:69-75`
`/^https?:\/\//i` misses protocol-relative `//host/…` and whitespace-prefixed hrefs. Those web destinations keep same-tab navigation, contrary to the comment at lines 70-71. This assumes DOMPurify keeps `//host` hrefs. Whether resource links can produce them is unchecked.
- Test: `expect(sanitizePreviewHtml('<a href="//example.org/x">x</a>')).toContain('target="_blank"')`

**3. Low, uncertain.** `resolveLessonReferences.ts:56-57`
`!post.refLabel` treats `''` as absent, but `??` on line 57 keeps `''`. A readable version with `refLabel: ''` renders an empty label rather than the fallback. Policy does not say which is intended.

**4. Uncertain.** `resolveLessonReferences.ts:48-50`
`select: { semver: true }` followed by `.map(v => v.id)`. If Payload omits `id` under `select`, `readableSources` is empty and every `compareHref` silently becomes null. I have not verified Payload's `select` behaviour.

**5. Uncertain.** `semver.ts:11` against `:23`
`bumpSemver` does no NaN coercion, while `parseSemver` uses `|| 0`. A stored `1.x.0` compares as `1.0.0` but bumps to `1.NaN.1`. This needs a malformed semver in the database, and write validation is unseen.

**6. Uncertain.** `semver.ts:111-115`
`nextSemverForPlan` on a plan with no versions returns `0.0.1`, not `1.0.0`. This matters only if a first version takes the patch path. Callers are unseen.

**7. Uncertain.** `stripIds.ts:8-14`
It removes every `id` key at any depth. `Object.entries` also turns non-plain objects into `{}`.
- Test: `stripIds({a:{id:'x', t:'y'}})` → `{a:{t:'y'}}`
- Test: `stripIds({d:new Date()})` → `{d:{}}`
- This matters only if bundle content has a meaningful `id` key or a Date value. Neither is checked.
