## Candidates

**1. Medium (confirmed by local reasoning).** `app/src/lib/identity/releaseFingerprint.ts:52-54`
- **Precondition:** a field holds an array whose entries all normalise to nothing, e.g. `[null]` or `[{}]`.
- **Expected:** the header (line 21) says empty arrays are dropped, so the output should match the input with that field absent.
- **Actual:** `value.map(normalise)` yields `[undefined]`. The array has length 1, so it is kept and serialises as `"tags":[]`.
- **Reproduction:** `releaseFingerprintInput({title:'T', meta:{tags:[null]}})` gives `{"meta":{"tags":[]},"title":"T"}`. `releaseFingerprintInput({title:'T', meta:{}})` gives `{"title":"T"}`. The hashes differ.
- **Impact:** if a stored copy carries such an array and the upload does not, identity comparison sees different content. That can refuse a set with "same id, different content" or create a spurious release. Fixing it changes the frozen format, so it needs an `ares-content-v2` decision, not an in-place edit.
- **Test:** the pair above should produce identical input. Whether Payload emits such arrays is unverified.

**2. Medium (confirmed by local reasoning; runtime exposure unverified).** `app/src/lib/loginProtection.ts:18-34`
- **Precondition:** the tracker records IPv4-mapped IPv6 addresses (`::ffff:a.b.c.d`), which a dual-stack listener can produce.
- **Expected (inferred from the comment at lines 14-17):** each distinct client gets its own budget. Mapping distinct IPv4 hosts to one key is a policy inference, so confirm before treating it as a defect.
- **Actual:** every mapped address is rewritten into `0:0:0:0::/64`. For example, `::ffff:c000:201` maps to that prefix, as does any other mapped IPv4 address.
- **Reproduction:** hold `withLoginCapacity` open for `::ffff:192.0.2.1`, then call it for `::ffff:198.51.100.7`. The second call returns 429 "busy" under the current code.
