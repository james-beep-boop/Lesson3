# F-C40-002 — taxonomy preview offers a subject its approval parser refuses

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: Low; Site-Administrator upload consistency edge.
- Evidence: locally reproduced over HTTP; no taxonomy writes on either refusal.
- Review: Sonnet supplemental F4 → Sol independent source/runtime critique → original-author recheck retained with amendments. New finding; audit only.

The JSON contract and `ingest/taxonomy.ts` allow a201-character subject into the missing-taxonomy offer. `endpoints/uploadBundles.ts:172` refuses the same subject when parsing its approval, because that parser caps names at200 characters. Preview and approval disagree about the same input.

Preview returns409, `needsConfirmation` and the exact offered name, with no new subject. Resubmitting those files with the exact approved subject returns400 and still writes no subject. The baseline-specific expected-approval assertion fails. This does not prescribe a later remedy: upfront rejection or accepting a consistently allowed name are both possible policy choices.

No large-payload denial of service was attempted on the running app. A separate capped one-CPU helper measurement at1k/2k/4k/8k characters took about10/43/69/303ms. That supports bounded algorithm-cost analysis, not an observed server outage or a severity upgrade. The ordinary200-character range is small. No security bypass, data corruption or school-wide impact is established.
