# F-C63-003 — text accepted during pending logout is lost

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: Medium; loss of newly accepted in-memory prose during an asynchronous logout.
- Evidence: source, isolated component, and actual Chromium/WebKit form plus PostgreSQL.
- Review: Haiku P062 lead → Sol independent source/runtime critique → Haiku original-author recheck confirms impact. Audit only.

`IdleLogout` takes `allSafe()` before awaiting logout and later navigates using that captured boolean. Installed Payload UI3.92 clears its local user immediately on logout, before the request settles. The toolbar changes to Viewing, but the textarea still accepts pointer and keyboard input. Recovery becomes inactive and unregisters its probe. Thus new text can arrive after the safety decision, with no capture, before the stale decision clears the page.

Reproduction: the two `lesson form keeps the last copy` cases in `app/tests/audit/browser.audit.spec.ts`. They run real native forms and actual delayed then forwarded logout requests. The browser wall clock alone moves past the cookie deadline; server time and native timer delays do not move. This isolates the focus-triggered backstop. In both Chromium and WebKit, text already unsafe before logout remains readable (control passes). A pristine form at the deadline accepts real pointer/keyboard text while logout waits, then loses the marker when the request completes: neither stored nor readable. Both preservation assertions fail. The initial harness incorrectly expected the Save button to stay available; the corrected repeated result checks actual accepted input instead.

The component reproduction in `expiry-race.audit.spec.tsx` separately demonstrates the stale safety decision. No production clocks, snapshots or authorization checks are altered. This is a controlled browser-clock reproduction, not an observed deployed incident or a two-hour wall-clock test.

A simple post-request `allSafe()` call is not established as a sufficient fix: inactive recovery unregisters, so an empty registry can report true. The author's recheck contains an inconsistent suggestion on that point; the coordinator rejects the sufficiency claim. The accepted finding is the observed lost input, not a prescribed implementation. Genuine native expiry is investigated separately.
