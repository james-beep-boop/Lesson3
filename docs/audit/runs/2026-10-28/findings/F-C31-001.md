# F-C31-001 — omitting UNIT bypasses the teacher's content boundary

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: Medium; scoped field-integrity failure in a newly created candidate.
- Evidence: source-confirmed and locally reproduced over real HTTP/PostgreSQL.
- Review: Sonnet supplemental lead → Sol independent source/runtime critique → original Sonnet author recheck confirmed. New finding; audit only.

The teacher branch of `hooks/fieldSplit.ts:308–311` restores administrator-owned top-level fields only when their keys occur in the submission. Omitting `unit` skips that restore. Unlike `finalExplanation` and `summaryTable`, UNIT has no unconditional rebuild. `endpoints/versionEdit.ts` then creates the new candidate from that incomplete content.

Expected: a teacher with editing access may change prose and must retain the source's administrator-authored overview. Actual: an authentic in-scope teacher POSTed a valid save-as-new multipart request with one prose edit and no UNIT key. It returned200 and the new candidate lost `unit.content`.

Reproduction: `app/tests/audit/field-omission.ts`. A trusted fixture seeds a source with administrator-authored UNIT content. A real scoped user signs in and submits the request. A trusted depth0 reread verifies the new candidate's missing content, and a full depth0 comparison proves the original snapshot is unchanged. The expected-preservation assertion fails. Fixtures are removed. The first draft of the harness compared different relation-population depths; the result above is from the corrected repeated run.

Limits: a crafted or incomplete client submission is needed; the ordinary editor submits UNIT. It creates a recoverable non-Official candidate, never mutates an existing snapshot and never promotes it automatically. Other omitted top-level fields are not included in this demonstrated claim. A future fix should cover omission and negative controls without changing native field-access behaviour.
