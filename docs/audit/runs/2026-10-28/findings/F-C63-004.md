# F-C63-004 — genuine expiry clears uncaptured prose instead of leaving it readable

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: conditional Medium; loss of accepted in-memory prose when capture and refresh fail through expiry.
- Evidence: repeated native HTTP/browser/PostgreSQL reproduction in Chromium and WebKit; source-based causal inference remains qualified.
- History: the broad native-timeout hazard was known as L3-13. Current SPEC§5 says both historical expiry paths are addressed. This is baseline counter-evidence to that resolved claim, not a claim that the general hazard was first discovered here.
- Review: Codex-origin investigation → Sonnet critique → Codex fuller runtime evidence → Sonnet amended confirmation → Codex policy/source recheck. Audit only.

The product explicitly gives the unsafe-work screen policy precedence when a final flush is unconfirmed (SPEC§5, baseline lines321–324). Confirmed captures are the durability guarantee; an unconfirmed capture need not magically be saved. The narrower expectation here is to leave the unsaved text legible so the teacher can copy it, as also documented in IdleLogout's screen-policy header.

Reproduction: `native session expiry preserves lesson text` cases in `app/tests/audit/browser.audit.spec.ts`. A native SDK issues a valid two-minute session using an isolated issuer's temporary in-memory setting; it is immediately restored. The running app configuration is unchanged, and browser/server clocks are real. The browser accepts the new text with Save enabled. Capture POSTs return simulated503 and refresh transport is aborted. Native start/read and logout/navigation remain real. After true expiry the server rejects the old JWT, the browser visits the inactivity route then sign-in, and neither recovery storage nor the readable page contains the marker. Both engines fail the preservation assertion, including a repeated run with full navigation history and manually opened final screenshots.

Control: with capture allowed to return200, both engines follow the same expiry route and retain the marker in the database; both assertions pass. Thus the experiment does not establish loss of server-confirmed drafts. Initial waitForURL observation returnedfalse because the intermediate inactivity route had already passed; the corrected route history resolves that measurement artefact. Two repeat invocations initially had incorrect browser dependency mounts/loader settings and ran no tests; only corrected executions count.

Installed Payload UI3.92 Auth's `onSessionExpiration` unconditionally logs out and redirects without consulting this application's recovery registry. That is a probable causal path, consistent with the observed foreground expiry. No function-call trace was captured, and IdleLogout can reach the same destination; navigation history alone does not prove which callback acted. F-C63-003 separately demonstrates text typed after IdleLogout's safe verdict while logout is pending. Keep these scenarios distinct, but do not assume they necessarily need unrelated fixes or count two proven root causes.

Limits: local ARM, small synthetic fixture, shortened valid token and selective network failures; no actual two-hour deployed incident, full outage or live-school reproduction. A future remedy must preserve shared-machine privacy and the explicit unsafe-work policy; no fix is included here.
