# F-C63-002 — literal marker text hides an invisible change explanation

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: Low; narrow restore-panel presentation defect.
- Evidence: deterministic execution of the real presentation helper and installed diff engine.
- Review: Haiku P059 lead → Sol source/runtime critique → original-author recheck confirmed with scope amendments. New finding; audit only.

`components/EditRecovery/restoreDiff.ts:149` recognizes a diff annotation using a substring search over output HTML. Literal prose containing `data-match-type` also matches. With an otherwise invisible newline change, the helper selects an unannotated diff instead of the explanatory “Paragraph breaks changed” note.

Reproduction: `app/tests/audit/restore-marker.audit.spec.ts`, run with the isolated audit Vitest config. `renderOf('data-match-type', 'data-match-type\n', false)` returns `{kind:'diff', html:'data-match-type'}`. The expected paragraphs result fails. This changes presentation only; no change to stored text or injection vulnerability is established.
