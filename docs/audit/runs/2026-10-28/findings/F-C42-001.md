# F-C42-001 — concurrent cold exports return a misleading validation error

- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Severity: Low; intermittent, retryable export preparation failure under same-spec concurrency.
- Evidence: repeated real HTTP/PostgreSQL controlled-overlap reproduction, installed adapter source.
- Status: new audit observation, independently reviewed; no fix included.
- Review: Codex-origin investigation → Sonnet confirmation with amendments → Codex repeated database controls/source recheck.

`exportVersion.ts:128–142` tries to coalesce simultaneous cold prepares onto one job. The recovery helper in `jobs/generateVersionArtifact.ts:155–168` recognizes the raw PostgreSQL23505 constraint and wrapped causes. The installed Drizzle adapter's `upsertRow/handleUpsertError.js` instead converts uniqueness violations into a fresh Payload ValidationError without carrying that driver constraint/cause. The endpoint rethrows it as400, “The following field is invalid: ”, instead of returning the winning job.

Reproduction: `app/tests/audit/export-concurrency.ts --barrier`, using only the separate disposable upgrade fixture. The existing `whileLockHeld` helper holds the jobs table in SHARE mode so reads proceed and inserts wait. Read-only pg_stat_activity inspection confirms all six actual native inserts are waiting before release. Three requests per format compete for two specs. Two requests return202 and four return400. A repeated controlled run gives the same split; trusted reads confirm exactly two pending jobs and a byte-equivalent original source snapshot. The expected all-coalesced assertion fails. This is proved overlap, not an inference from Promise.all alone.

An ordinary twelve-request run passes with two shared jobs and twelve complete matching artifact deliveries. This makes the failure intermittent in ordinary traffic; the barrier deliberately widens the window. The first exploratory run's400 bodies were not recorded, so those are not independently attributed to this cause. An immediate later retry exceeded the normal20/minute budget and correctly returned429; qualified runs wait for a fresh real window rather than reset counters.

The unique index still protects data. No duplicate jobs, wrong bytes, snapshot mutation, authorization bypass or school-capacity failure is demonstrated. The existing unit test supplies pre-conversion driver-shaped errors and therefore misses the actual adapter boundary. The reviewed installed adapter file's SHA-256 is `91979f049254dc65d630c46238d8cc1b9fa00602dd396bac8f584cf48e88409c`, matched to the source build's migration image; the Next runner bundles dependencies. Retry success is consistent with the endpoint logic and routine pass, but a losing request's exact retry was not separately exercised.
