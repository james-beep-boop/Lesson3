# F-C71-001 — SPEC older-content warning omits the no-manifest qualifier

- Severity: Low; documentation ambiguity, no demonstrated product defect.
- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Evidence: source/specification comparison; pending opposite-family review.
- Known status: new audit observation. Disposition: report only.

SPEC §7 says content equal to an older ARES release is flagged in confirmation, without limiting that sentence to files with no manifest. The approved Part 1 plan §3 explicitly introduces the warning under “Without a manifest,” because a new release ID can deliberately restore older text. `tests/unit/lessonReleases.spec.ts:78–83` explicitly pins warning-only-without-manifest, and `ingest/releaseDecision.ts:26–42` implements it.

The Haiku product-bug candidate was rejected after checking that fuller policy context. The actionable issue is the unqualified SPEC summary, which could mislead future implementation work. Clarify the sentence in a later authorized documentation change; do not change release behaviour as part of this audit.
