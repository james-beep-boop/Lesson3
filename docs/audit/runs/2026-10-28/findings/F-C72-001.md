# F-C72-001 — discussion title-search test depends on an earlier test

- Severity: Low; test-suite reliability, not a demonstrated product search defect.
- Source: `6e75a173e822e4c4be42821b0a4af48ca457bd36`.
- Evidence: source-confirmed and reproduced on Chromium; same dependency explains the corresponding WebKit failure after a worker restart.
- Known status: new audit observation, pending opposite-family review.
- Disposition: audit only; existing tests unchanged.

`tests/e2e/discussions.e2e.spec.ts:347–350` searches for the fixture's Dot topic. That topic is created by an earlier test at `:208`, not by the shared beforeAll or the search test itself. Running only the title-search test from a fresh fixture fails because the topic does not exist. A prior failure that restarts the Playwright worker can produce the same secondary failure.

Reproduction: run the existing Chromium suite with `--grep 'title search'` against the approved disposable stack. It fails on the missing Dot link. By contrast, the new isolated audit search case creates its own topic, then successfully finds it in both Chromium and WebKit.

Impact: filtered runs and recovery after an unrelated failure produce misleading search failures. This does not show that teachers' search is broken. Any later fix should make the test own its required data; no fix is included here.
