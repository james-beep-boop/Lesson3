# Version-write boundary map — C30/C31 (reconciliation in progress)

Contract: enumerate actual version writers and their guards, separate content immutability from permitted candidate deletion and trusted migration/fixture work. Existing passing suites do not prove every interleaving.

A TypeScript AST pass inventories literal create/update/delete calls and flags dynamic collection identifiers separately (version-write-sites.json). It excludes vendored code and generated types. This is a call-site aid, not whole-program proof: raw SQL, wrappers, request dispatch and scripts require reconciliation.

- Native caller create is closed for plans and versions (`access/versioning.ts`). Native update's form-render grant is paired with the first beforeChange hook `enforceVersionImmutable`, which rejects every authenticated update, including Site Administrators. Trusted migration writes without a user are an explicit exception. Unit wiring, native integration and HTTP denial/unchanged-row probes passed.
- `versionEdit.ts` creates candidates only after native authorization, stale-source comparison, field split, generatability and no-op checks; source deletion is separately authorized and transactionally coupled to the create. Recovery retirement tokens join that transaction. Original snapshots remain unchanged in the omitted-UNIT reproduction, but F-C31-001 demonstrates an incomplete field-split input can damage the new candidate.
- `make-official` changes the plan pointer and optionally deletes a named former Official in one transaction, with required stale-consent id and refreshed caller before commit. P017's proposed extra-lock requirement is not accepted: DECISIONS2026-08-14 explicitly considered and rejected that lock, and the cited interleaving does not delete an unconsented version. A different concrete failing ordering would be needed.
- `ingest/index.ts` creates fresh plans/releases under shared transaction and write-lock rules; it is trusted only behind the authorized upload endpoint or deliberate CLI. Confirmation is rechecked under locks, and the immutable snapshot gets its own version identity/fingerprint. F-C40-001 concerns plan identity normalization, not in-place version mutation.
- Plan deletion's `cascadeDeleteLessonPlanVersions` clears the pointer before deleting children, so the Official guard is not bypassed accidentally. Per-version deletion applies authorized grants and Official-row locking, then favorites/recovery cascades.
- Development seeding and the edit-recovery cascade verifier are explicit synthetic system writers. They are not HTTP authority. Restore imports database state through the technician backup workflow, rather than an ordinary collection mutation.
- Custom migrations write worldwide ids/fingerprints and ancestry/lineage via SQL. The clean-install and prior-release upgrade drills run those migrations; source-specific provenance/data-backfill review remains separate from generated DDL exclusion.
